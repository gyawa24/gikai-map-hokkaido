# 更新情報運用メモ

トップページの「更新情報」と `/news` は `site/data/news.json` を単一の真実源として表示する。

## いつ追記するか

- 機能追加
- 改善
- 修正
- 自治体追加
- 利用者に知らせるべき重要なお知らせ

原則として、関連実装と同じ変更単位で `site/data/news.json` に追記する。

## どう追記するか

手で `site/data/news.json` を編集してもよいが、形式を崩さないために次のスクリプト利用を推奨する。

```bash
node scripts/add-news-item.mjs \
  --date 2026-05-03 \
  --category 改善 \
  --title "タイトル" \
  --body "本文"
```

使えるカテゴリ:

- `機能追加`
- `改善`
- `修正`
- `お知らせ`
- `自治体追加`

## 文面の方針

- 利用者に伝わる言葉で書く
- 実装詳細より「何が変わったか」を優先する
- 誇張しない
- 日付は `YYYY-MM-DD`

## 確認ポイント

- `site/data/news.json` が JSON として壊れていない
- トップページの更新情報一覧に表示される
- `/news` の時系列表示でも崩れない

## 月次レビュー

月次レビューでは、更新情報が「公開済みの変化」と合っているかを確認する。

- 自治体追加、予算OCR、検索改善、記事追加など、利用者に見える変更が漏れていないか確認する。
- 内部ドキュメントだけの変更は、原則としてニュース化しない。
- 複数自治体の同種更新は、個別に並べすぎず1件にまとめる。
- Notion側で公開候補にした読みものがある場合は、`cd site && npm run articles:sync-notion` でMarkdownへ同期してから公開する。
- 同期した読みものがある場合は、`/news` と `/articles` の導線がズレていないか確認する。
- 日付、カテゴリ、本文が実際の公開タイミングと合っているか確認する。
