# 抽出テキスト品質チェック手順

作成日: 2026-05-09

この文書は、`data/processed/` に出力したMarkdownまたはテキストを、RAG投入前に確認するための手順である。AWS、RAG API、Knowledge Baseにはまだ投入しない。

## 目的

PDF抽出結果が、根拠資料として使える品質になっているかを確認する。

特に見ること:

- ページ番号で原文に戻れるか
- 空に近いページが多すぎないか
- 表や数値が崩れすぎていないか
- 見出し、章、節が残っているか
- 文字化けや不自然な記号が多すぎないか
- ヘッダー・フッターの繰り返しが多すぎないか
- 引用に使える粒度になっているか

## 対象ファイル

対象は `data/processed/` 配下の `.md` と `.txt`。

`scripts/extract_text.py` が出力したMarkdownでは、ページごとに以下の形式が入る。

```markdown
## Page 12

<!-- source_file: sample.pdf; page: 12; chars: 842 -->
```

品質チェックでは、この `## Page N` を使ってページ単位で集計する。

## 実行方法

標準出力だけで確認する。

```bash
python3 scripts/analyze_extracted_text.py
```

特定ファイルだけ確認する。

```bash
python3 scripts/analyze_extracted_text.py data/processed/2025_chitose_public_transport_plan.md
```

Markdownレポートも保存する。

```bash
python3 scripts/analyze_extracted_text.py --write-report
```

保存先:

```text
reports/extraction-quality-report.md
```

`reports/` 配下のレポートは再生成できるため、通常はコミットしない。

## 自動チェック項目

| 項目 | 内容 | 見方 |
|---|---|---|
| ページ数 | 抽出されたページ数 | 元PDFのページ数と大きくずれていないか |
| 総文字数 | 空白を除いた文字数 | 極端に少ない場合はOCRが必要な可能性 |
| 平均文字数 | 1ページあたりの平均 | 低すぎる場合は抽出失敗や図表中心の可能性 |
| 中央値文字数 | 文字数分布の中心 | 表紙や目次に引っ張られにくい |
| 空に近いページ | 文字数が非常に少ないページ | 図表ページなら許容、本文ページなら問題 |
| 短いページ | 文字数が少ないページ | 表紙、目次、図表、余白ページか確認 |
| 不自然な文字 | `�`、記号、制御文字など | 文字化けや抽出崩れの目安 |
| 繰り返し行 | 複数ページで同じ行が出るもの | ヘッダー・フッター候補 |

## 閾値

初期値は厳密な合否ではなく、目視確認の入口である。

| 閾値 | 初期値 | 意味 |
|---|---:|---|
| `--empty-threshold` | 20 | 空に近いページの文字数 |
| `--short-threshold` | 120 | 短いページの文字数 |
| `--min-repeat` | 3 | 何ページ以上に出たら繰り返し行と見るか |
| `--max-line-chars` | 80 | 繰り返し候補にする行の最大長 |

資料によって調整してよい。表紙や目次が多い資料では、短いページがあること自体は問題ではない。

## 人間が確認する観点

### 1. ページ番号

- `## Page N` がページごとに入っているか。
- 資料中のページ番号と大きくずれていないか。
- 引用時に「何ページを見ればよいか」が分かるか。

### 2. 見出し

- 章、節、施策名が残っているか。
- 目次だけでなく本文中の見出しも拾えているか。
- 見出しと本文が別ページに分断されすぎていないか。

### 3. 表

- 数値と項目名の対応が読めるか。
- 表が行ごとに崩れていても、原文に戻れるページ番号があるか。
- 金額、年度、目標値、割合が欠落していないか。
- 表だけで意味が取れない場合、RAG投入時の主根拠にしない。

### 4. ヘッダー・フッター

- 毎ページ同じ資料名、章名、ページ番号だけの行が大量に混ざっていないか。
- 繰り返し行候補に出たものが本文なのか、単なるヘッダー・フッターなのか見る。
- ノイズが多い場合は、除去ルールを入れる前に、原文への戻りやすさを優先して判断する。

### 5. 文字化け・記号

- `�` が多い場合は抽出失敗の可能性が高い。
- `□` や記号が多い場合、箇条書き記号や図表由来か、文字化けかを確認する。
- 1文字ずつ縦に崩れるページは、引用根拠として使いにくい。

### 6. 引用粒度

- 1ページ内に複数テーマが詰まりすぎていないか。
- 逆に、1つの表や説明が細かく分断されすぎていないか。
- 一般質問の根拠として、該当ページをすぐ見返せるか。

## 初回判断の目安

そのまま次に進めてよい:

- ほとんどの本文ページで文字数が十分ある。
- 見出しと本文が読める。
- 表は多少崩れても、数値と項目を原文確認できる。
- ヘッダー・フッター候補が少ない、または目視で無視できる。

いったん保留:

- 空ページ・短いページが多い。
- 本文が1文字ずつ縦に崩れる。
- `�` などの文字化けが多い。
- 表の数値と項目の対応がほぼ追えない。
- ヘッダー・フッターが本文より目立つ。

初回PoCから除外:

- OCRが必要な画像PDF。
- 図表や地図だけで本文がほとんどない資料。
- 個人情報や非公開情報の混入が疑われる資料。
- 公式公開資料かどうか確認できない資料。
