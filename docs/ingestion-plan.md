# 千歳市RAG PoC 資料投入計画

作成日: 2026-05-09

この文書は、千歳市公開資料RAG PoCで資料を投入する前の整理である。実装、AWSデプロイ、資料ダウンロード、S3投入はまだ行わない。

## 目的

- 初回投入資料を10〜20件に絞る。
- 公式公開資料だけを対象にする。
- OCRが必要な資料、個人情報リスクがある資料、非公開資料を初回から除外する。
- 回答時に、資料名、取得元ページ、可能ならページ番号を確認できる状態にする。
- まず小さく試し、引用精度と費用感を見てから追加資料を判断する。

## 初回投入の範囲

初回は行政計画・予算決算資料を中心にする。議事録は有用だが、行政計画資料と混ぜると根拠の性質が曖昧になるため、最初の同期では入れない。

| 区分 | 方針 |
|---|---|
| 初回投入 | 総合計画、教育、こども、防災、ゼロカーボン、交通、都市計画、予算決算 |
| 初回保留 | 環境基本計画、緑の基本計画、高齢福祉計画、公共施設計画、広報特集号 |
| 初回除外 | 議事録、個人情報を含みやすい資料、画像中心PDF、地図・図面中心PDF、大型PDF全文一括 |

## 初回投入から除外する資料

| 資料 | 除外理由 |
|---|---|
| 市民相談、陳情対応メモ、メール、LINE、議員個人メモ | 非公開情報・個人情報を含む可能性がある |
| 名簿中心の資料 | 個人情報や不要な個人属性を取り込みやすい |
| 個別審議会の詳細議事録 | 公開資料でも個人情報配慮が必要。初回検証では範囲外 |
| 市街地図、用途地域図、ハザードマップなど図面中心資料 | 画像・地図中心で引用精度の評価が難しい |
| スキャンPDF、画像PDF、OCR前提の資料 | 初回はテキスト抽出できる資料に限定する |
| 大型PDF全文一括 | 費用と抽出失敗リスクが大きい。章別・概要版を優先する |
| 古い計画の過年度版 | 最新資料との混同を招きやすい |
| イベント告知、募集、短期のお知らせ | 政策調査の根拠として寿命が短い |

## 取得元ページの扱い

- 本文中やメタデータの主URLは、PDF直リンクではなく公式の取得元ページを基本にする。
- PDF直リンクは、資料台帳の `download_url` にだけ記録する。
- 公式ページに複数PDFがある場合は、`source_url` は同じでも `file_name` と `title` で区別する。
- 取得日は `downloaded_at` として記録する。
- 取得元ページが削除・更新された場合に備え、資料タイトル、年度、所管部署を必ず残す。

## テキスト抽出時の注意点

- OCRが必要な資料は初回対象から除外する。
- 抽出後に、目次、見出し、ページ番号、表、脚注がどの程度残るか確認する。
- 数値、年度、計画期間、目標値は原文と照合する。
- 表が崩れる資料は、表の直前直後の説明文も一緒にチャンク化する。
- 図表だけで意味が伝わる箇所は、初回では根拠にしない。
- 抽出結果に文字化けが多い資料は、初回投入を見送る。

## チャンク分割の考え方

初回は複雑な最適化をしない。資料の章立てを尊重し、引用確認しやすい単位にする。

| 資料タイプ | 分割単位 | 注意 |
|---|---|---|
| 計画資料 | 章、節、施策項目 | 目標、現状、課題、取組を分断しすぎない |
| 予算・決算資料 | 事業、施策、会計、指標 | 金額と説明文を同じチャンクに入れる |
| 防災計画 | 編、章、節、役割分担 | 災害種別をメタデータに入れる |
| 交通計画 | 課題、基本方針、施策、評価指標 | 図表だけの箇所を根拠にしすぎない |
| HTML | 見出し単位 | ナビゲーションや問い合わせ先を混ぜない |

分割後の目安:

- 1チャンクは、1つの問いに答えるのに十分なまとまりを持たせる。
- ページ番号または章名で原文に戻れるようにする。
- チャンクを細かくしすぎて「結論だけ」「表だけ」にならないようにする。

## 個人情報・非公開資料を除外するルール

投入前に以下のいずれかに該当した資料は除外する。

- 公式公開ページから取得できない。
- 資料の取得元がメール、LINE、紙配布、内部共有フォルダである。
- 個人名、住所、電話番号、相談内容、個別事情が主な内容である。
- 議員活動上知り得た未公開情報を含む。
- 公開資料でも、個人への評価や個別判断に使われるおそれが高い。
- 公開範囲、利用可否、最新版かどうかが判断できない。

迷った資料は入れない。PoCでは資料数よりも安全性と引用確認を優先する。

## ファイル名ルール

ファイル名は英数字、ハイフン、アンダースコアで統一する。日本語ファイル名は避ける。

形式:

```text
{year}_chitose_{category}_{short-title}.{ext}
```

例:

```text
2026_chitose_general_plan_basic.pdf
2026_chitose_general_plan_implementation.pdf
2025_chitose_education_plan.pdf
2025_chitose_children_plan.pdf
2025_chitose_disaster_earthquake.pdf
2025_chitose_zero_carbon_plan.pdf
2025_chitose_public_transport_plan.pdf
2025_chitose_budget_overview.pdf
```

メタデータは同名ファイルに `.metadata.json` を付ける。

```text
2025_chitose_public_transport_plan.pdf
2025_chitose_public_transport_plan.pdf.metadata.json
```

## 保存ディレクトリのルール

ローカル準備段階では、実ファイルをこのリポジトリに入れない。まず台帳と手順だけを管理する。

将来の検証時の候補:

```text
rag-data/
  chitose/
    source-documents/
    extracted-text/
    manifests/
    evaluation-results/
```

AWS投入時のS3 prefix候補:

```text
s3://<検証用バケット>/docs/chitose/
```

初回PoCでS3に置くもの:

```text
docs/chitose/
  2025_chitose_public_transport_plan.pdf
  2025_chitose_public_transport_plan.pdf.metadata.json
```

## メタデータ項目

最低限、以下を付ける。

| 項目 | 必須 | 内容 |
|---|---|---|
| `file_name` | 必須 | S3上のファイル名 |
| `title` | 必須 | 資料名 |
| `url` | 必須 | 公式取得元ページ |
| `download_url` | 任意 | PDF等の直URL。本文には多用しない |
| `year` | 必須 | 年度または計画開始年 |
| `category` | 必須 | 総合計画、教育、防災など |
| `department` | 任意 | 所管部署 |
| `published_at` | 任意 | 公開日 |
| `downloaded_at` | 必須 | 取得日 |
| `priority` | 必須 | A / B |
| `source_type` | 必須 | PDF / HTML / other |
| `contains_personal_data` | 必須 | 原則 `false`。疑わしい場合は投入しない |
| `notes` | 任意 | 抽出時の注意、章別投入など |

例:

```json
{
  "metadataAttributes": {
    "file_name": "2025_chitose_public_transport_plan.pdf",
    "title": "千歳市地域公共交通計画",
    "url": "https://www.city.chitose.lg.jp/docs/23549.html",
    "year": "2025",
    "category": "交通",
    "department": "企画部",
    "priority": "A",
    "source_type": "PDF",
    "contains_personal_data": "false",
    "downloaded_at": "2026-05-09",
    "tags": "交通,公共交通,都市"
  }
}
```

## 更新確認の方針

初回PoCでは毎日更新を追わない。公開資料RAGは速報用途にしない。

| タイミング | 確認内容 |
|---|---|
| PoC開始前 | 公式ページが存在するか、最新版か、PDFが差し替わっていないか |
| 資料投入日 | `downloaded_at`、ファイルサイズ、ページ数、タイトルを記録 |
| 評価完了後 | 引用が古い資料に偏っていないか確認 |
| 本格運用前 | 月1回または議会前の更新確認フローを決める |

更新があった場合は、古い資料を残したまま新資料を追加しない。年度・版数を明確にし、古い資料を検索対象から外すか、過年度比較用として明示的に扱う。

## 投入前チェックリスト

- [ ] 公式公開資料である
- [ ] 取得元ページが確認できる
- [ ] PDF直URLだけに依存していない
- [ ] OCR不要でテキスト抽出できる
- [ ] 個人情報や非公開情報が主内容ではない
- [ ] ファイルサイズが初回PoCに適している
- [ ] 年度、所管部署、カテゴリが記録できる
- [ ] メタデータJSONを作れる
- [ ] チャンク分割後に原文へ戻れる
- [ ] 評価質問のどれに効く資料か説明できる

## 初回判断

最初の投入は10〜12件で十分。足りない場合も、すぐに資料を増やすのではなく、先に以下を確認する。

1. メタデータが足りているか
2. チャンクが大きすぎる、または細かすぎないか
3. 質問が広すぎないか
4. `n_queries` が適切か
5. 引用表示が原文確認に使えるか
