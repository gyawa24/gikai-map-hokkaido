# AWS RAG最小検証前チェックリスト

作成日: 2026-05-09

この文書は、千歳市RAG PoCでAWSを使う前の最終チェックリストである。まだ実装、AWSデプロイ、RAG API投入は行わない。

## AWS検証の目的

`genai-ai-api/aws/query-expansion-rag` を使い、資料1件だけで最小検証する。

目的:

- 回答品質を見る
- 引用品質を見る
- 費用感を見る
- AWS RAG構成を継続検証する価値があるか判断する

この段階では、源内Web接続、市民公開、本番運用、複数資料投入は行わない。

## 検証範囲

| 項目 | 内容 |
|---|---|
| 対象資料 | 千歳市地域公共交通計画 1件のみ |
| ローカルチャンク | `data/chunks/2025_chitose_public_transport_plan.jsonl` |
| 資料数 | 1件 |
| 公開範囲 | 本人用・検証用のみ |
| 市民公開 | しない |
| 本番運用 | しない |
| 検証対象 | 回答品質、引用元表示、費用、削除手順 |

資料を追加したくなっても、最初のAWS検証では増やさない。費用・引用・削除の流れが確認できるまで、資料1件に固定する。

## 事前確認

### AWSアカウント

- [ ] 検証に使うAWSアカウントを決めた
- [ ] 個人検証用または明確にタグ管理できる環境である
- [ ] 請求アラートを受け取るメールを確認した
- [ ] 検証開始日と終了予定日を決めた

### 使用リージョン

- [ ] 使用リージョンを決めた
- [ ] 原則 `ap-northeast-1` を使う
- [ ] 使わないリージョンにはデプロイしない
- [ ] Bedrockで使うモデルがそのリージョンで利用可能か確認した

### IAM権限

- [ ] CDKデプロイに必要な権限を確認した
- [ ] Bedrock、S3、OpenSearch Serverless、Lambda、API Gateway、CloudWatch Logs、KMS、WAFを扱う権限を確認した
- [ ] 本番環境や他プロジェクトを誤って触らない権限境界を確認した
- [ ] 削除操作に必要な権限も確認した

### Bedrock利用可否

- [ ] Bedrockのモデルアクセスが有効である
- [ ] 利用予定モデルのリージョン対応を確認した
- [ ] 埋め込みモデルの利用可否を確認した
- [ ] Advanced Parsingは初回では使わない方針を確認した

### S3

- [ ] 検証用S3バケット名またはCDK作成バケットの扱いを確認した
- [ ] 投入prefixを1つに限定する
- [ ] 投入資料は千歳市地域公共交通計画1件のみ
- [ ] `.metadata.json` に公式取得元URLを含める
- [ ] 検証後に資料とメタデータを削除する

### OpenSearch Serverless

- [ ] OpenSearch Serverlessが作成される可能性を理解した
- [ ] 小規模検証でも最低OCU課金が費用要因になることを確認した
- [ ] 検証後にCollectionが残っていないか確認する手順を決めた
- [ ] 最大OCUや関連設定を確認する

OpenSearch Serverlessは、このPoCで最も警戒する費用要因。使っていないつもりでも、Collectionが残ると費用が続く可能性がある。

### CloudWatch Logs

- [ ] ログレベルは `INFO` を基本にする
- [ ] `DEBUG` は使わない
- [ ] ログ保持期間を短めにする
- [ ] 検証後に不要なロググループを削除または保持期間短縮する

### CDK利用可否

- [ ] Node.js / npm が使える
- [ ] AWS CLIが使える
- [ ] AWS CDKが使える
- [ ] `cdk bootstrap` が必要か確認した
- [ ] `cdk destroy` の対象環境名を確認した

## 費用対策

### AWS Budgets

- [ ] AWS Budgetsを設定した
- [ ] 月額上限を低めに設定した
- [ ] 50%、80%、100%の通知を設定した
- [ ] 通知先メールを確認した
- [ ] Budgetsは通知であり、自動停止ではないことを理解した

Budgets通知を受けても、リソースが自動で止まるとは限らない。費用を止めるには、検証を止め、リソースを削除する必要がある。

### Cost Anomaly Detection

- [ ] Cost Anomaly Detectionを設定した
- [ ] 通知先を確認した
- [ ] AWSサービス別の異常検知を確認した
- [ ] 異常通知が来たら検証を止める運用を決めた

### 強く警戒する費用要因

| サービス | 費用リスク | 対策 |
|---|---|---|
| OpenSearch Serverless | 最低OCU課金、Collection残存 | 検証後に必ず削除確認 |
| Bedrock | 入力・出力トークン、埋め込み、RAG生成 | 質問数を絞る、詳細回答を常用しない |
| Bedrock Knowledge Bases | 同期・検索・生成に関連費用 | 資料1件のみ、同期回数を最小化 |
| S3 | 保存、リクエスト | 資料1件のみ、検証後削除 |
| Lambda | 実行回数、実行時間、メモリ | 質問数を絞る |
| API Gateway | リクエスト、ログ | 自分だけが使う |
| CloudWatch Logs | ログ取り込み、保存 | ログレベルを上げすぎない、保持期間を短く |
| KMS / WAF | キー・リクエスト・WebACL | 作成されたものを削除確認 |

## 削除対象リソース

検証後、以下を残さない。

- [ ] CloudFormation Stack
- [ ] Bedrock Knowledge Base
- [ ] OpenSearch Serverless Collection
- [ ] S3 bucket / S3 object
- [ ] Lambda function
- [ ] API Gateway API
- [ ] API Key
- [ ] CloudWatch Logs log group
- [ ] KMS key
- [ ] WAF WebACL
- [ ] IAM role / policy

削除後、当日だけでなく翌日以降もCost Explorerで費用増が止まったか確認する。

## セキュリティ

- [ ] 公開資料のみを使う
- [ ] 個人情報を入れない
- [ ] 非公開資料を入れない
- [ ] 市民相談、メール、LINE、議員メモを入れない
- [ ] AI回答を行政の公式回答として扱わない
- [ ] 回答は必ず原文と引用元を人間が確認する
- [ ] APIのアクセス元は自分のIPに限定する
- [ ] `0.0.0.0/0` のまま公開しない
- [ ] 市民公開しない

## 検証中の運用

- [ ] 質問数を少数に絞る
- [ ] `output_in_detail` を常用しない
- [ ] `n_queries` を増やしすぎない
- [ ] 検証中に資料を増やさない

- [ ] 異常通知が来たら質問実行を止める

## PoC結果レポートに書くこと

検証後、次に進む前に `docs/chitose-rag-poc-report.md` を作る。

最低限書くこと:

- 検証日
- 使用したAWSアカウントとリージョン
- 投入資料
- 質問数
- 回答品質
- 引用品質
- 誤回答
- 存在しない引用の有無
- 実際に発生した費用
- 削除したリソース
- 残ったリスク
- 次に進むか、中止するか

## 進行判断

AWS RAG最小検証へ進んでよい条件:

- 実行前チェックリストがすべて完了
- BudgetsとCost Anomaly Detectionが設定済み
- 資料1件だけに限定できている
- 削除手順を確認済み
- OpenSearch Serverlessの費用リスクを理解している

進まない条件:

- Budgets未設定
- Cost Anomaly Detection未設定
- 削除手順が不明
- 投入資料を増やしたくなっている
- 個人情報や非公開資料が混じる可能性がある
- 市民公開や本番運用の話が混ざっている

このチェックリストの目的は、AWS検証を止めることではなく、費用と安全性をコントロールできる状態で、最小の一歩だけ進めること。
