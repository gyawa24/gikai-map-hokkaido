# 千歳市公開資料RAG PoC計画

調査日: 2026-05-09

目的は、千歳市の公開行政資料を根拠に、地方議員の政策調査・一般質問づくりに役立つRAG型AI調査アシスタントを小さく検証すること。

## PoCの基本方針

- 市民公開しない
- まず本人用・検証用にする
- 個人情報、相談記録、未公開資料は入れない
- 公開URLがある資料だけを対象にする
- 回答には必ず根拠資料への引用を出す
- 原文確認なしで議会質問や発信に使わない
- AWS費用を毎日確認し、検証終了後は削除する

## 成功条件

| 観点 | 成功条件 |
|---|---|
| 実務性 | 一般質問の論点整理、担当部署への確認事項、過去資料の要点把握に使える |
| 根拠性 | 回答ごとに資料名・URL・可能ならページ番号が出る |
| 安全性 | 公開資料以外を投入せず、個人情報を質問にも入れない運用ができる |
| 費用 | 小規模検証の範囲で、日次費用が説明可能 |
| 再現性 | どの資料をいつ入れたか台帳で追える |

## 最初のデータ範囲

最初は10〜30資料に絞る。いきなり全庁資料を入れない。

優先候補:

| 分野 | 資料例 | 使い道 |
|---|---|---|
| 総合計画 | 千歳市総合計画、実施計画 | 市政全体の方向性、質問テーマ探索 |
| 予算・決算 | 予算書、主要施策、決算資料 | 事業費、経年変化、財源確認 |
| 子育て・教育 | 子ども・子育て計画、教育振興基本計画 | 一般質問の政策整理 |
| 福祉 | 地域福祉計画、高齢者、障がい福祉 | 制度・対象・課題確認 |
| 都市・交通 | 都市計画、地域公共交通、空港・基地関連資料 | 地域課題の論点整理 |
| 防災 | 地域防災計画、ハザード関連 | 災害対応・避難所・備蓄確認 |
| 議会資料 | 議事録、議案、委員会資料 | 過去答弁との接続 |

既存の地方議会ドットコムにある議事録データは有力だが、最初は「行政公開資料」と「議事録」を混ぜすぎない。まず行政資料だけでRAGの引用品質を見て、その後に議事録を足す。

## データ台帳

PoCでは資料台帳を作る。最低限の列は以下。

| 列 | 内容 |
|---|---|
| `file_name` | S3に置くファイル名 |
| `title` | 資料名 |
| `source_url` | 公開URL |
| `department` | 所管部署 |
| `year` | 年度 |
| `category` | 総合計画、予算、福祉など |
| `published_at` | 公開日。不明なら空欄 |
| `downloaded_at` | 取得日 |
| `contains_personal_data` | 原則 `false`。疑わしい資料は入れない |
| `notes` | 注意点 |

## メタデータ設計

Bedrock Knowledge Base用に、資料ごとに同名の `.metadata.json` を置く。

```json
{
  "metadataAttributes": {
    "file_name": "2025_childcare_plan.pdf",
    "url": "https://www.city.chitose.lg.jp/...",
    "tags": "子育て,計画,2025",
    "year": "2025",
    "category": "子育て"
  }
}
```

引用リンクに必要な `file_name` と `url` は必須にする。タグは検索絞り込みに使う。

## 質問セット

PoCでは先に評価用質問を作り、回答品質を毎回同じ基準で見る。

### 政策調査

- 千歳市の子育て支援で、今後重視されている施策は何ですか。
- 高齢者福祉で、資料上確認できる課題と対応策を整理してください。
- 防災備蓄や避難所運営について、現行計画で確認できる内容を教えてください。

### 予算・決算

- 子育て関連施策で予算規模が大きいものを、根拠資料つきで整理してください。
- 財政上の制約や今後の見通しとして資料に書かれていることを教えてください。

### 一般質問づくり

- この資料から一般質問にできそうな論点を3つ挙げ、確認すべき担当部署も示してください。
- 市民に説明しやすい形で、課題、現状、質問案に分けて整理してください。

### 安全性確認

- 資料に根拠がない質問をしたときに「確認できません」と言えるか。
- 似た制度名を混同しないか。
- URLやページ番号のない引用を根拠扱いしないか。

## 実装方針

### Phase 0: 調査のみ

今回のドキュメント作成。コード実装・AWSデプロイはしない。

### Phase 1: RAG API単体

`genai-ai-api/aws/query-expansion-rag` を1アプリだけデプロイ。

- アプリ名: `chitose-policy-rag`
- 資料数: 10〜30
- 質問数: 20程度
- `n_queries`: 1, 2, 3で比較
- `output_in_detail`: 原則false
- ログレベル: `INFO`
- IP制限: 自分のIPのみ

この段階では源内Webに接続しなくてもよい。curlで回答品質と費用を見る。

### Phase 2: 源内Web接続

RAG APIが使えると判断できたら、源内WebへAIアプリとして登録する。

- セルフサインアップ無効
- 共通チームまたは本人用チームだけ
- 不要な汎用機能を非表示
- AIアプリの入力欄は「質問」「検索の広げ方」「詳しい回答」程度に絞る

### Phase 3: 地方議会ドットコムとの関係整理

まだ市民公開しない。将来的には以下を検討。

- 地方議会ドットコムの公開検索とは別扱いにする
- 議員向け検証機能としてMCPまたは管理画面から使う
- 公開する場合は、回答ではなく根拠資料検索を中心にする
- 市民向けに出す前に免責、ログ、問い合わせ、誤回答報告導線を整える

## 回答プロンプト方針

千歳市PoCでは、デフォルトの「社内規約・利用マニュアル」向けプロンプトを使わない。

必須ルール:

- `<context>` の範囲だけを根拠にする
- 根拠が足りない場合は「資料内では確認できません」と答える
- 一般論で補わない
- 回答末尾に参考情報を出す
- 一般質問に使う場合は、確認すべき点を分ける
- 政策判断そのものを断定しない

回答フォーマット案:

```text
結論:
資料上確認できる内容を1〜3文で回答。

根拠:
どの資料のどの記述に基づくか。

一般質問にするなら:
確認すべき論点を箇条書き。

注意:
資料内で確認できない点、原文確認が必要な点。
```

## セキュリティ・個人情報

### 入れてよいもの

- 市公式サイトで公開されているPDF、HTML、Excel
- 議会で公開されている議事録・議案・委員会資料
- 既に公開されている統計資料

### 入れないもの

- 市民相談
- 住民の個別事情
- 未公開の行政資料
- メール、LINE、メモ
- 議員活動上知り得た非公開情報
- 個人名を含む苦情や相談記録

### 質問時の禁止

- 個人を特定できる情報を入れない
- 未公開の相談内容を貼らない
- 「この人にどう対応すべきか」のような個人対応判断をさせない
- 政治的攻撃文や断定的な批判文をそのまま作らせない

## 誤回答対策

| リスク | 対策 |
|---|---|
| 資料にないことを答える | 根拠不足時は確認不能と答えるプロンプトにする |
| 古い資料を根拠にする | `year` と `published_at` をメタデータに入れる |
| 引用URLがない | `url` メタデータがない資料は投入しない |
| 似た制度を混同する | 質問セットで検証し、カテゴリ・タグで絞る |
| 長文で費用増 | 通常回答を短くし、詳細回答は必要時のみ |
| 画像PDFを読めない | 最初はテキスト抽出できるPDF中心。画像PDFは後回し |
| 回答をそのまま使う | 「原文確認必須」をフッターと運用ルールに入れる |

## 評価表

各質問に対して記録する。

| 項目 | 判定 |
|---|---|
| 回答は質問に答えているか | ◎ / ○ / △ / × |
| 根拠資料リンクがあるか | 有 / 無 |
| 根拠は妥当か | ◎ / ○ / △ / × |
| 資料にないことを言っていないか | OK / NG |
| 一般質問づくりに使えるか | ◎ / ○ / △ / × |
| 費用が重すぎないか | OK / NG |
| メモ | 自由記述 |

## 地方議会ドットコムとの関係

当面は分ける。

- 地方議会ドットコム: 市民向けの公開情報検索・議会情報整理
- 千歳市公開資料RAG PoC: 本人用の政策調査補助

将来統合するなら、RAG回答をそのまま市民公開するのではなく、根拠資料検索、関連資料提示、質問作成メモのような補助機能に寄せる方が安全。
