# 地方議会ドットコム オープンデータ方針 v0.1

最終更新: 2026-05-30

この文書は、地方議会ドットコムが扱う議会情報を、再利用しやすい公共データとして整えるための方針をまとめる。
現時点では、公式な自治体オープンデータではなく、各自治体・議会が公開している資料をもとにした非公式の整理データとして扱う。

## 目的

地方議会ドットコムは、北海道内の市町村議会情報を、市民・議員・職員・研究者・報道・開発者が横断的に探せる入口にする。
そのために、画面で見やすくするだけでなく、出典・更新日・加工内容・品質状態を持った機械判読しやすいデータとして整備する。

重要なのは、単にデータを増やすことではない。
次の3点を満たす状態を目指す。

1. 出典が追える。
2. 加工や推定の有無が分かる。
3. 再利用時の注意点が分かる。

## 基本姿勢

### 1. 原典を置き換えない

議事録、議決結果、予算書、議会だより、一般質問要旨などの原資料は、各自治体・議会の公式サイトを正とする。
地方議会ドットコムは、原資料への入口と、横断検索・比較・再利用のための整理データを提供する。

引用、議会報告、報道、研究、政策判断などで正確性が必要な場合は、必ず公式サイトの原資料を確認する。

### 2. 権利と公開条件を混ぜない

本サイトのデータは、次の層に分けて扱う。

| 層 | 例 | 扱い |
|---|---|---|
| 原資料 | 自治体公式PDF、HTML、議会録画ページ | 各自治体・議会の利用条件に従う |
| カタログ情報 | 自治体名、資料名、公開日、URL、資料種別、確認日 | 本サイト独自の整理データとして再利用しやすくする |
| 構造化データ | 議員一覧、会議一覧、議案一覧、発言単位データ | 原資料の条件、加工内容、品質状態を明示して公開する |
| 派生データ | OCR、AI要約、テーマ分類、検索インデックス | 原文確認を前提とする補助データとして扱う |
| 運用メモ | 取得候補、保留理由、検証メモ | 原則として内部運用資料。公開する場合は文脈を付ける |

自治体や議会のページに複製・転載の制限がある場合、全文データを「オープンデータ」として再配布しない。
その場合でも、資料名、URL、公開日、確認日、資料種別などのカタログ情報は、出典を明示したうえで公開候補にできる。

### 3. 機械判読性を上げる

公開データは、画面表示のためだけのJSONにしない。
可能な限り、次の情報を持たせる。

- 安定したID
- 自治体slug
- 自治体名
- データセット種別
- スキーマバージョン
- 公式資料URL
- 確認日
- 公開日または会議日
- 加工内容
- 品質状態
- 権利・利用条件の確認状態

## データ分類

### 公開しやすいデータ

次のデータは、比較的オープンデータ化しやすい。

| データ | 理由 |
|---|---|
| 自治体一覧 | 基本メタデータであり、出典・更新日を明示しやすい |
| 掲載機能台帳 | 本サイト独自に整理した公開状態データ |
| 出典カタログ | 公式資料へのリンク集として再利用価値が高い |
| 議員名簿メタデータ | 公式サイトで公開されている公職者情報を整理したもの |
| 会議・資料インデックス | 原文本文ではなく、会議名・日付・URLなどの索引 |
| 議案・議決結果の索引 | 議案単位の結果表。資料条件を明示すれば再利用しやすい |

### 段階的に公開するデータ

次のデータは、原資料の利用条件や品質確認が必要なため、段階公開にする。

| データ | 注意点 |
|---|---|
| 議事録本文 | 議会ごとに著作権・転載条件が異なる可能性がある |
| 発言単位データ | 原文分割・話者抽出の加工が入るため、加工内容の明示が必要 |
| OCRテキスト | 誤認識があるため、原本画像やPDFへの導線を必ず残す |
| AI要約・テーマ分類 | 原文の代替ではなく補助データ。訂正依頼フローが必要 |
| 予算書ページOCR | 数字や表の誤読リスクが高く、原本確認前提にする |

### 公開しない、または慎重に扱うデータ

次のデータは、オープンデータとして扱わない。

- 非公開または限定公開の資料
- 公式サイトに公開されていない個人情報
- 問い合わせ、訂正依頼、運用上の内部判断メモ
- 権利条件が不明な第三者写真、ロゴ、キャラクター、地図素材
- AIが推定しただけで原典確認できない情報

## スキーマ方針

既存の `minutes`、`segments`、`sessions`、`decisions`、`publications`、`budgets` は、性格が異なる。
これらを無理に1つの形式へ押し込まず、まずはそれぞれの原データ構造を保つ。

そのうえで、再利用用の共通メタデータを横断的に持たせる。

```json
{
  "schema": "dataset_catalog.v1",
  "dataset_id": "shinshinotsu-publications",
  "municipality_slug": "shinshinotsu",
  "dataset_type": "publications",
  "title": "新篠津村 議会資料",
  "source_url": "https://example.jp/",
  "source_checked_at": "2026-05-22",
  "license_status": "source_terms_required",
  "transformation_level": "cataloged",
  "quality_status": "manual_reviewed"
}
```

### 推奨フィールド

| フィールド | 意味 |
|---|---|
| `schema` | スキーマ名とバージョン |
| `id` | データ内で安定するID |
| `municipality_slug` | `municipalities.json` と一致するslug |
| `dataset_type` | `members` / `minutes` / `sessions` / `decisions` / `publications` / `budgets` など |
| `source_url` | 公式ページURL |
| `document_url` | PDFやHTMLなど直接資料URL |
| `source_checked_at` | 最後に公式ページを確認した日 |
| `generated_at` | 本サイト側でデータ生成した日時 |
| `official_status` | `official` / `summary` / `ocr` / `derived` / `unknown` |
| `license_status` | `open_confirmed` / `source_terms_required` / `restricted` / `unknown` |
| `transformation_level` | `cataloged` / `extracted` / `normalized` / `ocr` / `ai_assisted` |
| `quality_status` | `raw` / `script_checked` / `manual_reviewed` / `needs_review` |
| `notes` | 利用者向けの注意点 |

## 利用条件の考え方

本サイト独自に作成したカタログ情報、索引情報、正規化メタデータは、将来的にCC BY 4.0相当で再利用できる形を目指す。
ただし、原資料本文や自治体・議会が著作権を持つ資料そのものについて、本サイトが新たな利用許諾を与えることはできない。

正式公開時には、データセット単位で次のいずれかを明示する。

| 表示 | 意味 |
|---|---|
| `本サイト作成メタデータ: CC BY 4.0相当` | 本サイトが整理したメタデータ部分は出典表記により再利用可能 |
| `原資料条件に従う` | 本文・PDF・画像等は公式サイトの利用条件を確認する |
| `再配布制限あり` | 公式サイトの条件により本文等の再配布を避ける |
| `確認中` | 権利・利用条件を確認中。再利用は原典確認を求める |

出典表記の例:

> 出典: 新篠津村議会「令和8年第1回定例会 議決結果」（公式ページURL、2026年5月22日確認）をもとに、地方議会ドットコムが資料名・議案情報・URLを整理。

加工したデータを利用する場合は、原資料そのものではなく、地方議会ドットコムが整理・加工したデータであることを明示してもらう。

## 公開形式

最初の公開形式は、JSONを基本とする。
CSVは、自治体一覧、議員一覧、議案一覧、会議一覧など表形式に向いたデータから対応する。

優先順位:

1. JSON: 既存データ構造と相性がよく、スキーマを保ちやすい。
2. CSV: 表計算ソフト、自治体職員、研究者が扱いやすい。
3. API: 検索・外部アプリ向け。ただしホスティング負荷を見ながら段階対応。
4. データカタログページ: 人間が一覧し、出典・利用条件を確認できる入口。

## 品質表示

データの品質は、利用者に分かるように段階表示する。

| 状態 | 説明 |
|---|---|
| `official_linked` | 公式資料へのリンク確認済み |
| `script_checked` | スクリプト検証済み |
| `manual_reviewed` | 人手で内容・出典を確認済み |
| `ocr_needs_review` | OCR由来で誤認識確認が必要 |
| `ai_assisted` | AI要約・分類を含む |
| `restricted` | 原資料条件により全文公開を控える |

品質表示は、利用者に不安を与えるためではなく、正しく使うための目印として出す。

## 実装ロードマップ

### Phase 0: 方針と棚卸し

- この文書を `docs/open-data-policy.md` として管理する。
- 既存データを、公開しやすいもの、条件確認が必要なもの、公開しないものに分類する。
- `publications`、`decisions`、`minutes` の境界を崩さない。

### Phase 1: カタログJSON

- `site/data/opendata/catalog.json` を作る。
- まずは次のデータセットだけ載せる。
  - 自治体一覧
  - 掲載機能台帳
  - 出典カタログ
  - 議会資料 `publications`
  - 予算書出典 `budget_sources`
- 各データセットに、出典、更新日、形式、利用条件、注意点を持たせる。

### Phase 2: `/opendata` ページ

- 市民・職員・開発者向けに、データセット一覧を表示する。
- ダウンロードURL、スキーマ、更新日、注意点を出す。
- 原資料の利用条件と、本サイト独自メタデータの利用条件を分けて表示する。

### Phase 3: CSV/API対応

- `municipalities`、`members`、`minutes_index`、`publications` からCSVを用意する。
- APIは軽量なカタログ取得を優先し、全文検索や本文配信は負荷と権利条件を見ながら分ける。

### Phase 4: 標準化提案

- 議会情報向けの標準データセット案として、項目定義を整理する。
- 自治体標準オープンデータセットにない「議会情報」領域の提案材料として使える形にする。

## やらないこと

- 原資料の利用条件を確認せず、全文をオープンデータとして再配布しない。
- OCRやAI要約を、公式発言や公式数字の代替として扱わない。
- `minutes` に一般質問要旨、議決結果、議会だより、会議結果を混ぜない。
- 市町村ごとの個別事情を消して、すべてを同じ品質に見せない。
- 利用条件が異なるデータを、1つの包括ライセンスでまとめない。
